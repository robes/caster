# Updating a project from the template

A project made from Caster (GitHub's "Use this template", or the zip) starts with
a copy of the files and a fresh history: no link back to Caster. So `git pull`
has nothing to pull from, and `git merge --allow-unrelated-histories` treats
every file both sides touched as a conflict. Caster still changes after you copy
it (fixes to `src/caster/`, the docs, the configs), and this is how to take those
changes later.

The method: tell git, once and only locally, that your first commit *is* the
Caster commit you copied. Then Caster's later commits merge as an ordinary
three-way merge: only what both sides changed conflicts.

## The first update

```bash
git remote add caster git@github.com:robes/caster.git
git fetch caster

# the Caster commit you started from: the one whose tree equals your first commit's
first=$(git rev-list --max-parents=0 HEAD)
base=$(git log caster/main --format='%H %T' \
  | awk -v t="$(git rev-parse "$first^{tree}")" '$2 == t {print $1}')
echo "$base"
# empty? You edited before your first commit, or started from a zip; take the
# Caster commit you copied (e.g. the last one before that date):
#   base=$(git log caster/main --until=<date> -1 --format=%H)

git replace --graft "$first" "$base"   # local only; never pushed (a signed first
                                       # commit warns its signature is dropped: fine)
git merge caster/main                  # resolve conflicts, then commit
git replace -d "$first"                # the merge commit now links the histories
```

The merge commit has `caster/main` as a parent, so the graft is never needed
again.

## Later updates

```bash
git fetch caster
git merge caster/main
```

## Resolving conflicts

- **`src/caster/`** is template-owned. Take Caster's side, unless you changed it
  on purpose, and then send that change upstream so the next merge is clean.
- **Your package, configs, `data_sources/`, `MODEL_CARD.md`** are yours. Keep
  your side and adopt any new structure the template introduced (a new required
  key, a new card field); Caster's commit messages name it.
- **Template examples you renamed or deleted** (`src/myproject/`, the
  `synthetic` dataset and its record): git reports their changes as
  modify/delete conflicts. Apply what you want by hand, then `git rm` them again.
- **`uv.lock`** is never merged by hand: take either side, then `uv lock`.

Before committing the merge, run `make check`, then `caster data validate` and
`caster package <release config> --dry-run`, which catch a record or config the
new template version reads differently.

## Alternatives

Template tools such as [Copier](https://copier.readthedocs.io/) (`copier
update`) and [cruft](https://cruft.github.io/cruft/) (for cookiecutter) do this
same three-way update for you, from a record of the template version stored in
the project. They need the project to have been generated by that tool; a
GitHub-template or zip copy was not, so the merge above is the route for it.
